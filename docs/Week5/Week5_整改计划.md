## 一、整改目标

### 1.1 总体目标

将项目从「可运行的 Alpha 技术原型」提升至「**微信可发行的 Alpha 产品**」，在内容深度、视听体验、商业闭环、平台兼容性四个维度达到策划方案中 Week 5 Alpha 里程碑的原始预期。

### 1.2 分阶段目标

| 阶段 | 周期 | 核心目标 | 对应优先级 |
|------|------|----------|------------|
| **第一阶段：止血** | Week 6（第 1 周） | 补齐内容缺口、接通变现链路、真机验证 | P0 |
| **第二阶段：固本** | Week 6–7（第 2 周） | 架构重构、视听升级、UX 打磨 | P1 |
| **第三阶段：进阶** | Week 7–8（持续） | 成长系统 MVP、CI 加固、文档同步 | P2 |

### 1.3 量化指标

| 指标 | 当前值 | 目标值（第一阶段完成） | 目标值（第二阶段完成） |
|------|--------|------------------------|------------------------|
| 可玩关卡数 | 15 | **30** | 30 |
| 真实音频资源数 | 0 | **≥8 个核心 SFX** | ≥12 个 |
| 微信真机 FPS（低端机） | 未验证 | **≥25fps（100 方块）** | **≥30fps（100 方块）** |
| 激励视频接入 | 0 条链路 | **≥1 条（复活）** | ≥2 条（复活 + 双倍金币） |
| 核心模块覆盖率 | ~17 文件 | **≥25 文件** | 全量核心玩法 ≥80% |
| Game.ts + GameScene.ts 行数 | ~1100 | **≤800** | ≤600 |
| 构建首包大小（gzip） | ~225KB | **≤200KB** | ≤180KB |

|------|------|
| **根因** | 无 MP3 资源，`playProceduralSfx` 作为兜底方案成为主方案 |
| **整改措施** | 1. 与 F-04 联动：导入真实 SFX 资源后，`AudioManager.playSfx()` 优先使用 `AudioBuffer`，失败时降级为程序音<br>2. 合并音效按 `newValue` 阶梯变化：value≤8 低频、16–64 中频、128+ 高频 + 混响<br>3. 增加「连击音效层级」：combo 2–4 播放基础音、5–9 叠加谐波、10+ 触发特殊音效<br>4. 编写 `AudioManager` 的音效优先级与降级逻辑的单元测试 |
| **验收标准** | 合并、连击、通关/失败各有独立可辨识音效；真机播放无明显延迟（<50ms） |

### 2.3 性能与响应速度（P-01 ~ P-05）

#### P-01：100 方块 ~20fps，策划要求低端机 30fps+【高】

| 项目 | 内容 |
|------|------|
| **根因** | 物理体全激活、粒子/GSAP 叠加、未充分利用休眠策略 |
| **整改措施** | 1. **强化 BlockPool**：静止方块（速度 < 阈值持续 500ms）设为 Matter `sleeping`，减少物理计算<br>2. **限制同屏粒子**：`ParticleEffect` 最大活跃粒子数 ≤30，超出时合并或丢弃旧粒子<br>3. **合并 Graphics 更新**：同一帧内多次 `MergeEffect` 合并为单次 `Graphics.geometry` 更新<br>4. **GSAP 优化**：HUD 动画使用 `gsap.ticker` 而非独立 `requestAnimationFrame`<br>5. 在 `PerformanceMonitor` 中增加 FPS 分级告警：<25fps 自动降低粒子质量、<20fps 暂停非必要动画 |
| **验收标准** | 微信低端机（骁龙 660 / 4GB RAM）100 方块场景稳定 ≥30fps；桌面 Chrome ≥55fps |
| **关联风险** | R-08（优化可能引入新 Bug） |

#### P-02：Pixi chunk ~1MB+（gzip ~225KB）【中】

| 项目 | 内容 |
|------|------|
| **根因** | 全量引入 PixiJS v8 |
| **整改措施** | 1. 在 `vite.config.ts` 中配置 `manualChunks`：将 PixiJS 拆分为独立 chunk，利用微信分包机制<br>2. 评估 PixiJS 的 tree-shaking 效果：仅导入实际使用的模块（`Container`、`Graphics`、`Text`、`Assets`），避免 `import * as PIXI`<br>3. 非核心场景（加载页、设置页）使用 Canvas 2D 降级渲染，减少 Pixi 实例数<br>4. 目标：首包 gzip ≤200KB（第一阶段）、≤180KB（第二阶段） |
| **验收标准** | `npm run build:wechat` 后首包 gzip ≤200KB；微信开发者工具「代码包」分析无冗余模块 |
| **关联风险** | R-09（Pixi tree-shaking 效果有限） |

#### P-03：性能数据仅桌面 Chrome【中】

| 项目 | 内容 |
|------|------|
| **根因** | 缺少微信开发者工具/真机性能采集流水线 |

| **验收标准** | 至少 3 款真机的性能基线数据归档至 `docs/Week5/性能基线/`；CI 可自动采集微信开发者工具 FPS |
| **关联风险** | R-10（真机设备获取困难） |
