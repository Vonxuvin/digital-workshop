**修复验证：**

mock 后 Game.test.ts 24 个测试全部通过，Game 类的业务逻辑得到完整验证。

### BUG-003：GameStateMachine 默认状态变更导致测试失败

| 字段 | 内容 |
|------|------|
| 缺陷ID | BUG-003 |
| 严重程度 | P0 |
| 发现日期 | 2026-05-09 |
| 状态 | ✅ 已修复 |
| 影响范围 | GameStateMachine 及依赖其的多个测试 |

**问题描述：**

GameStateMachine 的默认初始状态被更改为 `'boot'`，但现有测试和部分业务代码期望默认状态为 `'menu'`。此变更导致 GameStateMachine.test.ts 及多个依赖状态机的测试用例失败。

**修复方案：**

将 GameStateMachine 的默认初始状态恢复为 `'menu'`。`'boot'` 状态作为 Game 类启动流程中的显式过渡状态使用，而非 GameStateMachine 的默认值。这样既保留了 boot→loading→menu 的完整启动流程，又不破坏现有测试的预期行为。

**修复验证：**

默认状态恢复后，GameStateMachine.test.ts 12 个测试及所有依赖测试均通过。

### BUG-004：MergeSystem 缺少最大链深度保护

| 字段 | 内容 |
|------|------|
| 缺陷ID | BUG-004 |
| 严重程度 | P1 |
| 发现日期 | 2026-05-09 |
| 状态 | ✅ 已修复 |
| 影响范围 | MergeSystem 合并逻辑 |

**问题描述：**

MergeSystem 的合并链处理没有最大深度限制。在极端情况下（如大量方块同时触发链式合并），递归处理可能导致栈溢出或长时间阻塞主线程。

**修复方案：**

在 MergeSystem 中添加 `maxChainDepth=10` 参数，当合并链深度超过 10 时自动终止合并处理。此阈值足以覆盖正常游戏场景（通常链深度不超过 5），同时有效防止异常情况下的无限递归。

**修复验证：**

添加链深度保护后，压力测试中 100 次链式合并正常完成，无栈溢出。MergeSystem.test.ts 16 个测试全部通过。

### BUG-006：LevelLoader 缺少配置验证

| 字段 | 内容 |
|------|------|
| 缺陷ID | BUG-006 |
| 严重程度 | P1 |
| 发现日期 | 2026-05-09 |
| 状态 | ✅ 已修复 |
| 影响范围 | LevelLoader 关卡加载 |

**问题描述：**

LevelLoader 在加载关卡配置时未进行有效性验证，可能导致加载损坏或格式错误的配置文件后产生难以追踪的运行时错误。

**修复方案：**

在 LevelLoader 中添加 `validateConfig` 方法，对关卡配置进行结构化验证，包括：
- 必填字段检查（id、name、objectives 等）
- 数据类型验证
- 数值范围校验（如 gridWidth > 0）
- 目标配置完整性检查

验证失败时抛出明确的错误信息，便于快速定位配置问题。

**修复验证：**

添加验证后，LevelSystem.test.ts 中包含对无效配置的测试用例，均正确抛出验证错误。18 个测试全部通过。

### BUG-007：ScoreSystem 事件监听器 reset 时未清理

| 字段 | 内容 |
|------|------|
| 缺陷ID | BUG-007 |
| 严重程度 | P2 |
| 发现日期 | 2026-05-09 |
| 状态 | 📝 已记录（无需修复） |
| 影响范围 | ScoreSystem 重置逻辑 |

**问题描述：**

ScoreSystem 的 `reset()` 方法未清理已注册的事件监听器，可能导致在多次创建/重置场景后出现重复监听的问题。

**处理说明：**

经检查，ScoreSystem 的 `destroy()` 方法已正确清理所有事件监听器。在正常游戏流程中，场景切换时会调用 `destroy()` 而非 `reset()`，因此此问题不会在实际运行中触发。`reset()` 的设计意图是重置分数数据而非销毁实例。后续如需增强，可在 `reset()` 中添加监听器去重逻辑。
